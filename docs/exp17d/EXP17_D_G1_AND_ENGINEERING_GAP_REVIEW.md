# Exp17-D：历史 G1 继承边界与真实 Pair 工程缺口

本报告针对已交付提交 `e2ae411ecf6eb92511d83829388838693fd027b0` 做静态复核。结论是：**新建 Exp17 审核表为空，不代表历史用户没有接受过同源区域。应继承同一来源、Polygon、版本和实际资产的历史人工区域决定，只处理真实缺失或冲突的证据。** 历史 AI 建议、用户决定、资产选择、区域对应和正式训练准入仍是不同层次。

本报告只新增对账说明和后续工程建议，不修改 Exp14/Exp17 历史 CSV、代码、矩阵、协议或结果；没有重新看全量图片、重新制作审核页、运行测试或模型、生成、配准或优化。当前继承数量由本阶段独立逐记录对账清单和统计报告给出，不从新表的 `human_pass=0` 反推历史质量。

## 2. 历史人工决定不是仅凭文件名或整图 PASS 继承

[历史审核器](../../tools/exp14/large_scale_review.py) 的 `validate_review()` 校验 `review_id` 唯一性及冻结 `IDENTITY` 字段；逐 Polygon 决定仅能引用该审核记录的目标。区域确认要求 Aligned 存在，并要求整体或至少一个目标通过，随后实际核验 Aligned 和 Raw 哈希。页面的 `renderPolygon()` 展示“原图局部”和“Aligned 同位置局部”，`render()` 同时展示原图轮廓、当前 Aligned、既有版本，存在 Bounded 时单独展示。

[A9 身份整合器](../../tools/exp14/final_dataset_identity.py) 的 `reconcile_review()` 延续这些定义：

- `explicit` 必须是同条记录冻结 Polygon 集合的子集。
- `resolved = explicit.get(pid, row["decision"])` 是历史代码明确使用的同条默认规则。继承时要保留 `EXPLICIT` 或 `OVERALL_DEFAULT` 的来源，不能把默认解释伪写成新的逐 Polygon 点击。
- B 路线还需要 `b_region_review=CONFIRMED`；因此不是只看 `whole_image_normal=YES` 就把整图结论扩散为区域接受。
- `audit_variant()` 绑定来源、专业 JSON、请求、Mask、Raw、Aligned、Valid Mask、保存矩阵和目标局部。它核验 `before` 是原图相应裁剪，`after` 是同版 Aligned 相应裁剪，并保存目标无效像素数。

[A9 B 选择器](../../tools/exp14/final_dataset_selection.py) 的 `b_proposals()` 在语义确认后，排除身份隔离、目标无支持、矩阵不可用及特定结构/人机冲突；`priority()` 优先像素身份已绑定、风险较少、显式目标决定，版本号仅作稳定排序。它不等于“默认最新 V4”或“从多个版本拼出一次 PASS”。`variant_rows()` 在 [final_dataset.py](../../tools/exp14/final_dataset.py) 保留具体输入、版本、显式/解析后的目标决定、资产身份和最终版本选择。

A9 报告已记载：语义前置条件覆盖 623 个去重 Polygon / 639 个版本与 Polygon 组合，进一步筛选后留下当前 545 个候选；这几个数的分母不同。545 个 B 候选按生成定义已具有人工作用域和同版本通过证据，仍需本次逐记录验证其原 CSV 行、版本和实际资产对应，不能靠定义跳过本次核验，也不能说它们全部只有 AI PASS。

### 2.1 人工范围必须保留，但不能凭词语捏造裁剪范围

历史逐目标 PASS、仅区域确认、整图待核备注以及实际限定裁剪，应分别记录。若原决定明确只接受一个局部或给定裁剪视野，继承仅适用于该范围；范围外不自动成为伪正常。不应仅因备注出现“局部”“窗口”就臆造一个没有证据的裁剪坐标。

整体 HOLD/重配准与某个显式目标 PASS 可以并存。应读取同一版本的目标状态和区域确认，不把整体失败自动传播给所有目标，也不将局部 PASS 提升为整图可空标签。A 路线的整帧有效像素/全部七类标签要求不能套到 B 的局部接受上。反之，B 局部接受不能替代 A 整图标签准入。

### 2.2 `NEEDS_HUMAN_ASSET_CONFIRMATION` 不等于没有 Aligned

`b_proposals()` 在第五批或存在 `bounded.png` 时设置这个状态。它是当时对“用户实际认可哪种像素版本”的保守提醒，并不是一次独立的“Aligned 文件缺失”检查；同一函数仍保存 Aligned/Valid/矩阵和审核身份。当前 180 条该标记不能不经核对就解释为 180 次修复失败或必须重看 180 张图片。

最小处理是复用原审核记录、备注、实际查看资产和已绑定哈希，判断 A9 推荐的具体 Aligned 是否就是已接受对象。若已明确，不再重审；若 Raw/Aligned/Bounded 的接受对象确有歧义，只澄清该对象。A8 V4 的空 `final_version_choice` 不能由程序替用户补选，也不能自动否定同源其他已经明确接受的旧版本。A9 的建议列与用户选择列必须继续分开。

### 2.3 历史几何文件链接缺项不等于没有保存矩阵

A9-D0 已解释 B 清单中 246 条旧几何文件链接为空、但矩阵仍保留的情况。旧 Exp17 [audit_assets.py](../../tools/exp17/audit_assets.py) 的 `geometry()` 通过历史 `review_id`、来源/Aligned 哈希、记录文件和同一保存矩阵恢复可核对关系，并区分“有历史整文件 SHA”与“只有固定矩阵和资产链、今天新核验文件 SHA”的来源强度。后者应继续标注溯源限制，不能伪造历史哈希；它也不等于错矩阵或需要重新配准。是否存在实际绑定异常由本次精确对账给出，不因旧链接列为空就要求重做 SIFT/RANSAC 或 G2。

## 3. G0、G1、G2 的名称不能混淆

A9-D0 将 G0 定义为同来源、同 Polygon、同版本的人工语义确认；旧 Exp17 的 `G0_PASS` 则主要表示本轮文件、类别和坐标身份核验通过。二者名称相同，不能据此把一次技术身份检查称为新的人类 G1，也不能因新增人类 G1 列为空而忽略已有人工语义确认。

A9-D0 的 `region_metrics()` 在既有原图/Valid 网格内生成目标外扩窗口。`eligible_pixel_support()` 检查目标完整支持、ROI 有效像素至少 95%、目标外上下文有效像素至少 90%。`assess()` 的研究试验还要求：同一机械部件、目标修复入窗、可比上下文、结构 CLEAR、捷径 CLEAR，以及至少两个边界站；其位移上限为 `min(0.10 × ROI对角线, 0.50 × 目标短边)`，并加入 `0.03 × ROI对角线` 的取点不确定性上界。

这些规则有明确的 **36 例 counterfactual pilot** 出处，并非已经获独立数据 Gate 批准的全量契约。该函数返回 `coarse_geometry_qualified_formally=False` 和 `training_approved=False`。应保留既有测量，不重新跑几何或补点；不能把“没有两个试验边界站”视为历史用户否决，也不应把数值筛查未达试验扩窗阈值直接标成用户 REJECT。目标实际落在有效区域、正常参照是否对应正确部件仍是必须核对的实体问题。

G2 的独立机械点、Formal TRE 和历史密集变化 Mask 任务需要自己的证据。当前 J2 的目标是**区域级同源语义对应**，本阶段用户明确不要求像素级/亚像素精配准、独立几何点重测或完整 G2。SIFT/RANSAC 拟合内点不能冒充独立验证是合理的来源纪律，但它不推出“所有历史区域接受都必须重新采点”。

旧 Exp17 的 `G1_REJECT` 中若来源是 D0 的 `G1_PILOT_FAIL`，其归属是该次 Codex 研究试验观察，不能计成“历史用户明确拒绝”。实际异常应保留并针对性解释；新的历史用户状态必须来自具体人工 CSV 和适用版本，而非从标签名称推断。

## 4. 新 Exp17 G1 字段：继承、新记录与真实缺口对照

| 新字段/要求 | 可以继承的历史证据 | 真正需要补充的情况 | 不应施加的重审门槛 |
|---|---|---|---|
| `same_mechanical_part`、`context_correspondence` | 同版 Original/Aligned 及同位置局部已人工比较，来源/Polygon/变换身份吻合，且没有相反的范围说明 | 明确不是同一部位、历史配准身份冲突，或原备注保留无法对应的问题 | 因新字段 PENDING 再确认全部同一机械结构 |
| `defect_removed`、`mechanical_structure_preserved`、`normal_texture_plausible` | 同版本目标 PASS + 区域 CONFIRMED，继承原接受及限制 | 缺陷仍在、明显结构幻觉/部件遮蔽，或旧决定明示未解决 | 以新措辞再次否定已经明确接受的同版本修复；要求与原图逐像素一致 |
| `target_support_complete` | 既有 Valid Mask、原 Polygon 和目标支持记录，A9/旧 Exp17 已核验其绑定 | 目标实际无效、资产被更换、坐标或版本不一致 | 要求整幅图或整个新增扩窗完全有效，才允许一个完整支持的历史接受目标进入 Gate |
| `independent_boundary_evidence` | 历史同机械边缘/孔槽/上下文对照与区域接受；记录其原 CSV 和证据身份 | 存在真实的部位对应歧义或未解释结构冲突，只查对应记录 | 新的独立取点、两边界站、Formal TRE/G2，或要求重新描述已明确接受的同版机械对应 |
| 新 `reviewer_id`、`reviewed_at`、`boundary_evidence_note` | 保留原人工输入 SHA、行号/唯一键、`review_id`、确认动作和原备注作为历史来源 | 只在原记录缺失/冲突或需用户作一个新选择时补新记录 | 伪造旧字段，或因为旧 schema 没有这些列而使全部旧决定失效 |
| `seam_or_blur`、纹理/亮度差异 | 保留旧观察与人工接受的实际范围 | 严重接缝/模糊破坏所用目标区域或构成实质捷径，且未由历史接受解释 | 任何可见纹理、亮度或非目标变化一律自动 REJECT；要求所有风险布尔项均为“绝对不存在” |
| `UI_or_FOV_shortcut` | 已有审核、实际资产和视野范围 | 未解决的严重 UI/视野差异确实可充当 A/N 状态标识 | 任意 UI 像素或全图差异自动视为严重捷径 |
| `other_defect_contamination` | 原专业 JSON、同版各目标状态、实际正常参照池化支持及接受范围 | 其他缺陷进入**实际使用的正常参照区域**，或同版状态确实不一致 | 另一缺陷只在较大的展示 ROI 或同一张图上，就自动否定一个不受污染的已接受目标 |
| 新表全部正向 YES、全部风险 NO | 是新表自身 `validate_review()` 的导出完整性规则 | 对真正新增审核可继续以该工具记录 | 把新导出表视为历史接受的唯一有效证据，要求 545 条重新填表 |

这里“继承”是带原始来源的证据映射，不是把旧决定自动改写成新表十二项 YES/NO。新继承清单应保留历史字段和新字段之间的区别，使用 `INHERITED_REGION_PAIR_CANDIDATE` 表示可以交独立 J2 Data Gate 审查，而非伪造一次今天的新人工 PASS。

## 5. 修正后的 Data Gate 建议

1. **按资产键继承。** 从 A9 已推荐候选出发，核对 source/group、Polygon/类别/坐标、review/variant/run/version、原图/专业 JSON、Raw/Aligned/Valid、矩阵、原 CSV 哈希和行身份。复用已有核验结果及精确清单；不重新生成或配准。
2. **区分状态及归属。** 历史用户 ACCEPTED、带范围 ACCEPTED、PENDING/HOLD、REJECTED、AI-only、未定版本、未定配准、资产错配、无决定分开；同版本区域通过不能与另一版本像素混用。既有 AI 观察不冒充用户决定。
3. **仅解决具体残缺。** 已明确的机械对应、缺陷修复和范围不重复审核。确有 Raw/Aligned/Bounded 选择空项、互相矛盾的范围或实际结构/污染问题时，列出确切缺口和要回答的一个问题，保留旧记录。
4. **不按粗筛标签推翻历史。** 源级版本冲突、ROI 触框、其他标注在展示窗内、轻微纹理差和历史研究边界站缺失均是待解释信息，不是自动用户拒绝。确有错版本、错矩阵、目标无有效支持、真实未修复/结构幻觉、明确拒绝或严重未解决捷径则 HOLD/排除该具体记录。
5. **独立审计后才冻结可用清单。** 本轮继承候选可以大于零，新表人工点击仍可为零；这不自动产生 Formal Trusted Pair 或训练授权。不能为了凑够 15—30 组而放宽质量，也不能因 Tip curl 无候选而猜造类别覆盖。

本轮用户的继承要求修正了旧 Exp17 把“新增人类 G1 表”当作下一步唯一入口的安排。旧报告/零值按其时间点保留，新增 D 记录说明解释变更，不改写旧协议或将其无声解锁。

## 6. 已完成的工程证据应完整复用

旧 Exp17 的 21 项 CPU 测试、3 次合成 GPU 联合更新、A/B/N 共享图、120 个 Backbone 张量 Pair 梯度、N 分支梯度、单优化器、BN/RNG 保护、严格 checkpoint/EMA/AdamW/Scaler 重载和投影头剥离证据均保留。详见 [既有原型报告](../../results/exp17_j2_preparation/prototype_report.md)。本轮不重复运行。

实现 [pair_loss.py](../../tools/exp17/pair_loss.py) 继续使用 Exp15 的 P3 Polygon 池化、归一化公共投影和 `8×SupCon`；`source_ranking()` 对 B 来源组和 A 来源组/类别取均值，避免把多个变体算成独立来源。`auxiliary_batch_statistics()` 在 N 路径保留 TRAIN batch-stat 语义、禁用 running-stat 跟踪、恢复 RNG 和标志；原型已有完整 N=A 一致性证据。没有必要重新设计损失、投影头或训练器。

这些结果只证明合成数据上的共享计算图与数值路径。原型仍有 `real_pair_training_gate()` 无条件拒绝、`select_synthetic_bindings()` 只接收合成对象、`ReplayTrace` 只覆盖合成矩阵/RGB 合同。新数据可继承与真实训练可执行不是同一结论。

## 7. 五个真实工程缺口及最小后续路径（本轮均不执行）

| 缺口 | 可直接复用 | 最小新增工作和需要的证据 | 不允许的捷径 |

### 7.1 只需覆盖冻结协议实际启用的增强，但必须保留原生调用

冻结 [J-B 正式协议](../../results/exp15_jb/formal_protocol.json) 的几何/颜色有效变化包括 scale/translate、水平翻转和 HSV；mosaic、mixup、copy-paste、cutmix 等关闭。最小适配应围绕当前锁定 Ultralytics 8.4.117 的实际调用和实例排序，避免开发通用增强框架。关闭某项增强不代表可以重写主流程或删掉原生调用；即使某操作不生效，也不能擅自改变随机数消耗和已有 A 张量。

[jb_binding.py](../../tools/exp15/jb_binding.py) 的 `AuditedFormat.apply_instances()` / `check_formatted()` 已展示如何在原生 Format 边界独立重建掩码面积排序、重叠 ID、类别和框身份；未来适配可复用此核验方法。但该现有检查不包含来源 Polygon 稳定 ID 贯穿真实增强的实现，不应宣称真实回放已完成。

### 7.2 区域接受与全批 N 输入的接口需要明确，不应借机扩大审核

原型要求完整同槽 N 批，是为了两路使用一致的批统计语义，不代表每张 N 的所有位置都获得“正常”标签。对历史仅接受局部的记录，未来 manifest 和池化必须保留此局部范围；未接受区不能被作为新的正常参照或整图无缺陷证据。

完整 N 前向的感受野和 batch statistics 仍可能受范围外内容影响。这个问题应如实列为输入构成/捷径风险，结合既有上下文诊断及实际拟用区域处理；不能因此要求所有局部接受升级为整图正常重审，也不能在本轮擅自引入新裁剪、拼贴或替换修复结果。若解决它需要改变既定方法或实际资产构成，应提交具体设计 Gate，而非将旧接受清零。

### 7.3 后续顺序与停止点

最小路径为：**D 历史继承对账 → ChatGPT 独立 Data Gate → 新增薄真实适配层及身份/回放验证 → 单独授权的真实 TRAIN 校准与容量/有界工程验证 → 冻结正式协议与 Formal Gate**。需要实际更新的工程验证必须另获许可，不能由本报告推导。历史已有的测试和合成预算不重做、不重置；没有必要重新训练 J0/J1。

若原生回放不能保持主任务轨迹、同槽版本发生真实冲突、实际参照受其他缺陷污染、目标不被 Valid 支持、数值或容量失败，保留证据并停止对应记录/工程步骤，不自动换版本、调参或放宽设计。本轮没有真实 Pair 参数更新、VAL/TEST、修复生成或配准权限。
