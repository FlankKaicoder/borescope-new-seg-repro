# Exp17-D historical user decisions and scope

This is metadata reconciliation of existing human evidence, not a new visual review. The five original CSVs, A9 registries, historical matrices and existing Exp17 results remain unchanged. No image was opened for this analysis, no registration or raster was recomputed, and no model was loaded. Current blank Exp17 review fields do not invalidate earlier user decisions.

These are review-row counts, not independent sources or Pair counts. A review family can contain a newly aligned older generated version: for example, the second review includes old Raw alignment recoveries. Use each record's actual generation version, review ID and asset hashes, rather than assuming the CSV family equals generation V1/V2/V3/V4.

A5/A6/A7/A7B/A8 reports explicitly label their initial AI results as pending human confirmation. Those initial AI PASS counts differ from the later exported user PASS counts above. A user may explicitly adopt an AI suggestion; after that confirmed export it is a user declaration even if its explanatory note retains the AI wording. Conversely, an unconfirmed AI PASS is not a historical user acceptance.

## Frozen A9 interpretation to preserve

The authoritative [`reconcile_review`](../../tools/exp14/final_dataset_identity.py) validates the CSV review identity against its exact record and parses explicit Polygon decisions only within that record's frozen target set. `resolved[pid]` uses an explicit decision when present; otherwise it uses the same record's overall decision, as the historical UI specified. This default must not be replaced by a new rule that calls every empty explicit map unreviewed.

The separate [`b_proposals`](../../tools/exp14/final_dataset_selection.py) condition additionally requires both `resolved[pid] == PASS` and `b_region_review == CONFIRMED`. It then checks the saved mapping, target Valid Mask support and the frozen conflict rules. Thus B admission candidacy was never generated by bare whole-image PASS alone.

For the current **545 selected Polygon/version combinations**, all have the corresponding historical user PASS, B CONFIRMED and resolved same-Polygon PASS. Their region-level semantic evidence should be inherited. All have same-version Aligned/Valid/matrix identities in the established audit chain. This does not create formal Data Gate PASS or certify every possible future crop, context or image-loading choice.

The selected list uses 377 review identities for 376 source images. One image has different accepted versions for two different Polygons. Those regional bindings can both be valid individually; a future full-slot counterfactual loader must not silently combine their different repaired pixels into one image. It must use one coherent admitted version per actual image slot or skip the conflicting Pair, preserving main-task sampling.

## Scope that must follow acceptance

| Historical qualification among the selected 545 | Polygons | Source images | Independent source groups |
|---|---:|---:|---:|
| B region confirmed but no whole-image-normal YES | 23 | 10 | 10 |
| Human note explicitly retains local result while reserving whole-image judgment | 14 | 7 | 7 |
| Union of those two qualifications | **37** | **17** | **16** |

The two Polygon sets do not overlap, but their independent source-group sets do. These 37 already accepted regional results need their existing scope retained, rather than repeated proof of regional acceptance. A YES in a broad checkbox must not erase a narrower note. Neither a regional PASS nor these counts authorizes full-frame empty-label training.

No explicit historical cropped-FOV rectangle was established by the selected notes inspected here. That is an evidence-description result, not proof that every earlier image used a full field of view. Words such as “window”, “local” or “crop edge” describe many mechanical views or display crops and cannot manufacture a new accepted crop rectangle. Keep the exact accepted Polygon/version and any documented restriction; do not extend acceptance outside a known historical view.

## Pixel choice and version conflict are distinct

A9 marks **180** selected Polygons `NEEDS_HUMAN_ASSET_CONFIRMATION`: 100 actual V2, 37 V3 and 43 V4. The frozen trigger is the final review batch or the availability of a Bounded alternative. These records still carry specific Aligned hashes and matrices. The flag does not mean their image bytes or historical regional decision are absent.

All 31 V4 `final_version_choice` fields are blank. That source-level final-selection queue must remain recorded, but it must not invalidate a separately bound earlier accepted version or turn all 545 regional decisions into missing human evidence. Nor may this reconciliation invent a final Aligned/Bounded/old-version selection. An existing note explicitly identifying Aligned as the basis of a local acceptance is useful narrow evidence; retain the A9 pending-pixel state alongside it until the independent Data Gate resolves the actual asset choice.

The A9 source-level `version_conflict` flag includes multiple whole-image candidate versions and whole-image human/AI disagreements. It is not proof that the particular selected Polygon/version has conflicting human decisions. Report source-level flags, same-Polygon alternatives and actual per-slot incompatibility separately. A rejected old version cannot reject another accepted version by association, and an old accepted version cannot approve new pixels.

## Meaning of the 84 excluded historical combinations

Calling the unchanged A9 proposal function on its saved verified metadata reproduces **639** semantic Polygon/version combinations: **555** eligible under the frozen proposal rules and **84** ineligible. The 84 involve 82 distinct Polygons and 57 independent source groups. None is an exact currently selected combination. Four of their Polygon IDs have another usable version among the current 545, which must retain its own identity.

| Frozen reason combination for the 84 | Version/Polygon combinations |
|---|---:|
| Human/AI Polygon conflict | 54 |
| Human/AI Polygon conflict and mechanical-structure conflict | 23 |
| Target Valid support insufficient | 4 |
| Human/AI Polygon conflict and target support insufficient | 2 |
| Human/AI Polygon conflict, support insufficient and mechanical conflict | 1 |

These remain outside the current candidate list; this task does not rescue them or relabel their user decisions. In particular, “ineligible under A9 conflict/support rules” is not synonymous with “user explicitly rejected”. Counting 84 failures inside the already selected 545 would be incorrect.

## Targeted questions instead of another full review

The old D0 pilot contained 15 cases held chiefly for absent dual independent boundary stations or unquantified references. This evidence format is not a universal new requirement for regional J2 correspondence. If the same mechanical region and target removal were already accepted and identities agree, those cases do not need another geometric-point exercise or Formal TRE.

Of the 11 old visual-ambiguity cases, this metadata reconciliation retains six specific target/structure questions; the other five chiefly describe tight ROI, soft focus, highlights or weak references and are not automatically disqualified. The four old D0 pilot failures are Codex diagnostic observations, not user REJECT. Their actual UI or domain-risk content remains visible.

The new private semantic overlay identifies **12 exact Polygon/version questions in 12 independent groups**, with each source document, SHA256, locator and quotation:

| Question level | Exact cases | Treatment |
|---|---:|---|
| Recorded camera overlays removed inside the historical target window | 3 | Specific UI-risk question for Data Gate |
| Target-state/remnant or reconstructed opening/boundary ambiguity | 6 | Clarify only the recorded state question |
| Pronounced grain/sharpness difference | 1 | Domain-risk evidence; texture alone is not automatic failure |
| Full-frame UI removal whose relevance to the actual pooled region needs definition | 2 | Resolve regional/forward scope, without blanket whole-frame rejection |

These questions **do not revoke the historical user PASS**, create user REJECT, or establish permanent exclusion. They are independent Data Gate agenda items. Generic brightness/texture changes, an arbitrary ROI touching another annotation, or the new `independent_boundary_evidence` form being blank are insufficient on their own to force re-review. Actual target-support loss, a wrong version/matrix, unresolved severe UI/structure errors or contamination of the actual normal reference remain real constraints.

The private scope and question rules are bound to exact review ID plus Polygon ID. They never apply a source-wide wildcard to another version. Historical CSV rows and existing Exp17 results remain untouched. The separate reconciliation report supplies the complete 545-row matrix and all Polygon/source-group counts; formal trusted Pair remains subject to the independent ChatGPT Data Gate.
