# EXP18 Checkpoint 存储修订 V2

V2 在独立 worktree 接续 `11c514dea1fb3190f27c4881aa52660876b4b06a` 的 CPU_READY 证据。固定三臂 J1、A1-True、A1-Shuffled，Seed42、Batch32、H200/4200 更新，H100 是独立备用。科研协议、原始资产、封存数据轨迹、匹配与输入文件均沿用之前身份。存储配置使用独立 SHA。既有 CPU 技术验收和用户转述的独立科学审查结果作为前序依据。

## 保存和恢复

| 产物 | 保存策略 |
|---|---|
| 完整永久状态 | H200 每臂 E0/E100/E200，H100 每臂 E0/E50/E100，全年程端点均保存 |
| 完整滚动状态 | 每 5 Epoch 一个，最多两份。命中永久轮次时引用同一完整状态 |
| Best | MASTER 和 EMA 独立选择，各自最多一个当前权重或永久档引用 |
| Last | 最终永久档导出的 FP32 MASTER 和 EMA 权重。合成验收检查去除两类训练头、可回读 |
| 批次缓存 | 每臂两轮，一个独占构建空间，保留所有生成清单、精确内容 SHA 和退役记录 |
| 审计及评价 | Journal、诊断、逐图预测、匹配报告与收据保持不可变 |

完整恢复状态包含 MASTER、EMA、BN、AdamW 槽及更新计数、Scaler、Scheduler、CPU RNG、模型模式与 backend 策略、逻辑数据及匹配游标、配置/数据/源码/协议和 Journal 身份。真实 CUDA RNG 字段由现有 native checkpoint 合同覆盖，当前 V2 运行入口只接受 CPU-only Torch 与显式合成模型。Loader 以 Epoch 边界恢复，worker 内部状态由未来冻结的 epoch seed、精确输入重建和验证覆盖。

每条 Journal 使用 canonical JSON、序号、前一行 SHA 和执行身份。流程如下。

1. `ATTEMPT_BEGIN` 预留逻辑步。完成前向、反向、裁剪、更新、EMA 后写 `UPDATE_EXECUTED`，记录内容和完整状态摘要。有效更新以 Checkpoint 确认的前缀为准。
2. 每 105 更新将完整状态独占写入新版本，flush、fsync、回读并验证。状态包含写入前的 Journal 摘要及字节位置。随后 `CHECKPOINT_COMMIT` 绑定文件、状态摘要和被评价的两个角色。最新已验证状态始终独立于正在发布的版本。
3. 轮换先提交新版本，再为最旧版本写退役预约。只移除本次运行拥有、唯一链接且 SHA 一致的指定 payload，保留目录、旧回执和收据链。训练端点与评价全部提交后同样退役剩余正常恢复槽。Checkpoint 缺失、部分写入、数据或回执损坏保留现场并 HOLD。
4. 每 5 Epoch 提交该轮恢复状态后再写诊断并运行既定 `MASTER_STANDARD`、`MASTER_FIXED`、`EMA_STANDARD`、`EMA_FIXED`。每个 pass 单独记录 `VALIDATION_BEGIN`/`VALIDATION_COMMIT`，绑定模型角色、准确状态、Checkpoint、预测 manifest 和逐图成员哈希。一个已开始而未提交的 pass 进入 HOLD。
5. 新进程重开持久 lease，核验完整链和资产回执后恢复最新锚点。追加未持久化训练段的 `SEGMENT_ABANDONED` 和新的恢复记录，重算至当前进度并核对已观察步的状态 SHA。已提交的 VAL 从回执恢复。E150 已提交、E154 中断时从 E151 重做，单次正常恢复上限 105 步。HOLD 及人工核验前，异常保留不做重试。物理训练尝试与 4,200 逻辑有效更新分别计数。

Best 沿用既有 Standard 原生规则，即 Mask AP50–95 加 Box AP50–95，平分选较晚 Epoch。两角色可以来自不同轮次。只有角色状态与永久档准确绑定时才引用永久档。旧 Best 权重按同样的归属和 SHA 划定范围进行替换，选择证据保留。主终点是 E200 Last MASTER 七类 Mask AP50–95。

## 诊断与覆盖

逐步记录组件损失、裁剪前后范数、AMP、LR、A/N 与增强/匹配哈希、优化器计数和状态摘要。使用本次前向已经算出的 A1 gap、pair loss 和类别身份，记录排序正确率与类别统计。联合梯度按模型域汇总。主与辅独立梯度及其方向不从联合梯度推断，留给专门标定。额外诊断新增真实模型前向/反向预算为 0。

读封存元数据核验 4,200 步后，K=100,867/S=22,437 曝光，521/497 唯一区域，327/316 来源组。Shuffled 实际伙伴共有 6,265 条 A→N 聚合边。497 个有监督 A 中 18 个只有一个观察伙伴，涉及 95 / 22,437 曝光（0.42%）。其中 3 个只有一次曝光，15 个有多次。联合交叉表共 145 行，其 52 个正 K 细分单元与既有独立审计一致。空分母留空，唯一 Polygon 与来源组在每种投影重新取并集。CSV 放在 [覆盖证据目录](../../results/exp18_cpu/storage_v2/coverage)。

## 容量

原 13,203 个完整状态的参数和 AdamW 矩理论下界约 564.35 GiB，三臂保留全部 Epoch 的 A/N 图像张量另约 646.09 GiB。两项合计约 1,210.44 GiB，另有 masks、BN、预测、序列化等。V2 以 9 份永久状态、最多 6 份滚动状态和一次发布峰值计价。历史 R5 完整状态约 44.51 MiB，按该参考尺寸，9 份约 0.39 GiB，15 份约 0.65 GiB。基于已封存 shape/dtype 与 N 槽计数，两轮活跃像素张量约 7.36 GiB，正常单 builder 下约 8.73 GiB，非相邻恢复情形以更保守的单轮 N 上限计算。

容量回执把历史字节、合成测量、计算项、真实待测项分开，比较周期 5/10/20/25/50 轮的完整状态数及重放开销。V2 正式容量式使用实测上界计入 Best/Last、Journal、诊断、三臂 480 pass 的 VAL、缓存、重建和失败证据空间，并预留至少 8 GiB 或峰值的 20%，取较大值。现有约 45 GiB 的历史空余量没有通过正式容量 Gate。
